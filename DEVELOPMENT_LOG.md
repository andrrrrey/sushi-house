# 2026-09-17 — Углублённая диагностика SIP-регистрации Mango

- Перехвачен полный обмен при чистом запуске Asterisk: обычный `REGISTER` с `Expires: 180` получает штатный Digest challenge `401`, после авторизованного повторного запроса Mango возвращает `403 Forbidden` с внутренним текстом `77ee12`.
- Подтверждено, что DNS, UDP-порт `60000`, обратная доставка SIP-пакетов, NAT и доступность регистратора работают; `OPTIONS` получает `200 OK - keepalive`.
- Проверено отсутствие начальных/конечных пробелов и переноса строки в сохранённом SIP-пароле без раскрытия значения.
- A/B-тест `Contact: 225` вместо полного идентификатора не изменил результат.
- A/B-тест адреса регистрации `225` при сохранении полного Digest-логина не изменил результат.
- A/B-тест Digest-логина `225` не изменил результат.
- Порт `5060/UDP` не дал успешной регистрации; рабочий для обмена с данным узлом порт — `60000/UDP`.
- После тестов исходная конфигурация восстановлена, временная копия с секретом удалена.
- Основная оставшаяся гипотеза: переданное значение `400338531/225` может быть логином сотрудника для Личного кабинета/Контакт-центра, а не SIP-ID отдельной SIP-учётной записи. Для продолжения требуется полный SIP-адрес и пароль непосредственно из карточки SIP-учётной записи Mango либо подтверждение поддержки по серверному журналу и коду `77ee12`.

# 2026-09-22 — Нормализация номера для исходящего SIP-вызова

- По API Realtime установлена точная причина неуспешной попытки: Mango завершила вызов менее чем за секунду с кодом `1131` («вызываемый номер недоступен»), до открытия аудиоканала.
- Хранимый тестовый номер по-прежнему проверяется и хранится в международном формате `+7…`.
- A/B-проверка показала, что для этой SIP-учётной записи Mango российский номер назначения должен передаваться как `8XXXXXXXXXX`: вызов получил `200 OK`, был отвечен и перешёл в состояние `Connected`.
- Для российских номеров SIP URI теперь формируется в формате `8…`; исходящий Caller ID остаётся в формате `7…` без плюса.
- Добавлен модульный тест номера назначения и Caller ID.

- Робот озвучивает номер заказа, все позиции и модификаторы, сумму, город, улицу, дом, квартиру, подъезд, этаж и домофон, затем просит подтвердить состав и адрес.
- Данные заказа добавляются в системный контекст YandexGPT; модель не может подменять их и сообщает, что подтверждение остаётся только в тестовом журнале.
- Подтверждение и отказ распознаются быстрым локальным сценарием без дополнительного ожидания YandexGPT.
- SpeechKit теперь генерирует PCM 16 кГц с пиковой нормализацией; backend выполняет сглаженное преобразование в телефонные 8 кГц.
- AudioSocket читается непрерывно во время синтеза и воспроизведения, поэтому старые аудиофреймы не накапливаются между репликами.
- Воспроизведение переведено на монотонный таймер по 20 мс, чтобы сетевые задержки не создавали разрывы между фреймами.
- Пауза определения конца реплики сокращена с 700 до 500 мс.
- На сервере прошли 26 автоматических проверок; живая read-only проверка iiko нашла заказ с позициями и адресом.
- После развёртывания healthcheck приложения и SIP-регистрация Mango имеют статус `healthy` / `Registered`.
- Версия приложения: `0.8.0`.
