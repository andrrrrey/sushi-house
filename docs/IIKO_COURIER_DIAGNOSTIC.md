# Почему назначенные курьеры не были найдены через iikoCloud API

Первичная проверка: 15 сентября 2026 года.

Права на чтение сотрудников повторно проверены: 17 сентября 2026 года.

## Краткий вывод

Назначенные курьеры передаются через iikoCloud API. Причина результата «курьеров: 0» — неправильная обработка структуры ответа и, вероятно, ограничение выборки первыми 50 заказами.

Утверждение о том, что курьеры назначаются только в локальном iikoTransport и не синхронизируются с iikoCloud, не подтверждается фактическим ответом API.

## Признаки неправильной проверки

### Получено ровно 50 заказов

Результат ровно в 50 заказов обычно означает одно из следующего:

- в запросе установлено `rowsCount: 50`;
- обработана только первая ограниченная выборка;
- проверена не вся совокупность организаций;
- выполнение остановлено после первого ответа.

При контрольной проверке только одной организации «Шумяцкого» API вернул:

- 188 заказов;
- 111 заказов с назначенным курьером.

Следовательно, выборка из 50 заказов не является полной проверкой данных за период.

### Проверено неправильное поле курьера

Курьер находится не в поле:

```text
order.courierInfo.name
```

Правильный путь:

```text
wrapper.order.courierInfo.courier.name
```

Структура ответа выглядит следующим образом:

```json
{
  "ordersByOrganizations": [
    {
      "orders": [
        {
          "order": {
            "courierInfo": {
              "courier": {
                "id": "COURIER_ID",
                "name": "COURIER_NAME",
                "phone": "COURIER_PHONE"
              },
              "isCourierSelectedManually": false
            }
          }
        }
      ]
    }
  ]
}
```

## Правильный пример парсинга

```python
for group in response.get("ordersByOrganizations", []):
    for wrapper in group.get("orders", []):
        order = wrapper.get("order") or {}
        courier_info = order.get("courierInfo") or {}
        courier = courier_info.get("courier") or {}
        courier_name = courier.get("name")
```

Проверка должна учитывать, что `courierInfo` или вложенный объект `courier` могут иметь значение `null`, если курьер для конкретного заказа ещё не назначен.

## Результаты контрольных проверок

Проверка по всем доступным организациям за двухдневный период ранее показала:

- 1280 полученных заказов;
- 756 заказов с назначенным курьером;
- отсутствие ошибок iikoCloud API.

Повторная проверка одной организации «Шумяцкого» показала:

- 188 полученных заказов;
- 111 заказов с назначенным курьером;
- наличие значения по пути `order.courierInfo.courier.name`.

## Что необходимо исправить

Для корректной проверки требуется:

1. Получать заказы по всем необходимым организациям.
2. Не ограничивать итоговую проверку первыми 50 заказами.
3. Обрабатывать все элементы массива `ordersByOrganizations`.
4. Обрабатывать все элементы вложенного массива `orders`.
5. Читать имя курьера из `order.courierInfo.courier.name`.
6. Не считать отсутствие курьера у отдельных заказов отсутствием данных о курьерах во всём API.

После этих изменений назначенные курьеры должны корректно определяться в ответах iikoCloud API.

## Проверка доступа приложения к сотрудникам

У текущего приложения iiko есть фактический доступ на чтение справочников сотрудников. Это проверено реальными запросами с сохранёнными `API Login`, `App ID` и `Client Secret` приложения.

Во время проверки персональные данные не выводились: для общего списка сотрудников запрашивалось только поле `id`, а результат оценивался по HTTP-статусу и счётчикам ответа.

### Фактические результаты

| Метод | Назначение | Результат |
|---|---|---|
| `POST /api/1/employees/couriers` | Курьеры доступных организаций | HTTP 200, получено 10 записей |
| `POST /api/employees/v1/employee/list` | Общий список сотрудников | HTTP 200, `totalCount: 4540` |
| `POST /api/employees/v1/positions/list` | Справочник должностей | HTTP 200, `totalCount: 99` |

Приложению доступны 10 организаций. Дополнительная настройка прав со стороны интегратора для этих трёх методов сейчас не требуется.

### Получение списка курьеров

```http
POST /api/1/employees/couriers
Authorization: Bearer ACCESS_TOKEN
Content-Type: application/json
```

```json
{
  "organizationIds": [
    "ORGANIZATION_ID"
  ]
}
```

В ответе используется массив `employees`. Этот метод относится к группе ограничений iiko `Drivers: dictionaries` и возвращает сотрудников, являющихся курьерами в указанных организациях.

### Безопасная проверка общего списка сотрудников

```http
POST /api/employees/v1/employee/list
Authorization: Bearer ACCESS_TOKEN
Content-Type: application/json
```

```json
{
  "filters": [],
  "fields": ["id"],
  "limit": 1,
  "offset": 0
}
```

Ответ содержит:

- `items` — запрошенную страницу сотрудников;
- `totalCount` — общее количество подходящих записей;
- `limit` и `offset` — параметры пагинации.

Метод поддерживает поля `id`, `code`, `firstName`, `lastName`, `middleName`, `name`, `phone`, `email`, `cardNumber`, `mainRoleId`, `roleIds`, `isSystem`, `isFired`, `hireDate`, `fireDate`, `note`, `mainOrganizationId`, `organizationIds` и `responsibleForOrganizationIds`.

Следует запрашивать только поля, действительно необходимые сценарию. Телефоны, email, номера карт и другие персональные сведения нельзя выводить в журналы диагностики.

### Получение должностей

```http
POST /api/employees/v1/positions/list
Authorization: Bearer ACCESS_TOKEN
Content-Type: application/json
```

```json
{
  "filters": [],
  "limit": 100,
  "offset": 0
}
```

Метод возвращает страницу должностей и общий счётчик `totalCount`.

## Текущее состояние нашей реализации

Необходимо различать права приложения и уже написанную функциональность:

- доступ iiko API к курьерам, сотрудникам и должностям подтверждён;
- общий метод `IikoClient.post()` технически позволяет выполнять эти read-only запросы;
- текущая страница iiko в админке пока не содержит отдельного справочника сотрудников;
- сейчас в интерфейсе отображается только имя курьера, назначенного конкретному заказу, из `order.courierInfo.courier.name`;
- получение списка сотрудников не требует изменения заказов и должно оставаться отдельной операцией только на чтение.

Если будет добавлен раздел сотрудников, нужно обязательно реализовать пагинацию, фильтрацию по организациям и признаку `isFired`, минимальный набор возвращаемых полей и запрет записи персональных данных в технические логи.
