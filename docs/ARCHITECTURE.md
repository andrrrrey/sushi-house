# Архитектура технического MVP

## Компоненты

- **Backend:** Python, FastAPI, SQLAlchemy/Alembic.
- **Админка:** серверные страницы с минимальным JavaScript; отдельный SPA на первом этапе не требуется.
- **База:** PostgreSQL.
- **Телефония:** Asterisk с PJSIP; управление тестовыми вызовами через ARI/AMI.
- **iikoCloud:** отдельный клиент с диагностикой, повторными запросами и безопасным журналированием.
- **Reverse proxy:** HTTPS после подключения домена; до этого доступ через SSH-туннель.
- **Развёртывание:** Docker Compose для приложения, Asterisk и базы; SIP/RTP публикуются только на основном IP сервера.
- **Сетевая защита:** цепочка `DOCKER-USER` принимает SIP только от `81.88.86.0/24`, а RTP — от `81.88.88.0/23`.

## Потоки MVP

### Mango

1. Asterisk регистрирует выделенную SIP-учётную запись робота.
2. Входящий контур выключен по умолчанию. После ручного включения dialplan принимает только сохранённый тестовый номер, остальные вызовы отклоняет до ответа.
3. AudioSocket передаёт PCM 8 кГц в backend; SpeechKit распознаёт и синтезирует речь, а YandexGPT формирует структурированный ответ и полное состояние черновика.
4. Исходящий тестовый вызов запускается вручную только на разрешённый номер.
5. Расшифровка, реплики робота, тип обращения и локальный черновик отображаются в разделе «Входящие».
6. При жалобе, изменении принятого заказа, возврате или явном запросе оператор вызывается перевод на настроенную внутреннюю группу после заданной задержки.

### iikoCloud

1. Backend получает токен по API v2.
2. Читает организации, терминальные группы, опубликованное внешнее меню, цены и стоп-листы.
3. Опрашивает доступные методы заказов и сохраняет диагностический результат.
4. До отдельного разрешения не подтверждает, не отменяет и не изменяет заказы.

## Управление секретами

- В базе хранятся только зашифрованные значения.
- Главный ключ шифрования передаётся окружением сервера и не хранится в базе или Git.
- Интерфейс позволяет заменить секрет и проверить подключение, но не раскрывает сохранённое значение.
- Логи содержат только тип интеграции, время, результат и безопасное описание ошибки.

## Второй этап

После приёмки голосового MVP бизнес-функции робота будут оформлены как серверные инструменты с явной валидацией: получение заказа, подтверждение данных, перевод оператору и разрешённые изменения iiko.

## База знаний

- Начальные правила загружаются идемпотентно и далее редактируются в админке.
- Записи с отметкой «Требует уточнения» не попадают в контекст робота.
- Персональные промокоды и данные гостей из исходной таблицы не импортируются.
- База знаний не заменяет валидацию меню: позиция заказа принимается только при сопоставлении с действующим внешним меню iiko.
