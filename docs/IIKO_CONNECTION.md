# Подключение к iikoCloud API

Актуальная инструкция для проекта Sushi House Voice Robot.

Дата обновления: 15 сентября 2026 года.

## 1. Создание приложения

На портале разработчика iiko необходимо создать приложение типа `server-to-server`.

После создания приложения выдаются:

- `API Login` — ключ доступа клиента iiko;
- `App ID` — идентификатор приложения;
- `Client Secret` — секрет приложения.

Обычные логин и пароль пользователя iikoWeb для этой интеграции не используются.

Секретные значения нельзя хранить в Git, исходном коде или открытых журналах. В приложении они сохраняются в зашифрованном хранилище через раздел «Настройки».

## 2. Настройка со стороны клиента или интегратора iiko

Приложению необходимо предоставить доступ к нужным организациям и включить получение:

- организаций;
- терминальных групп;
- внешнего меню;
- стоп-листов;
- доставочных заказов;
- заказов из Starter;
- статусов заказов;
- информации о назначенном курьере.

Назначенный курьер передаётся во вложенном поле:

```text
order.courierInfo.courier.name
```

Для текущего сценария используется имя курьера. Телефон курьера в административной панели не выводится.

## 3. Авторизация

Запрос:

```http
POST https://api-ru.iiko.services/api/v2/access_token
Content-Type: application/json
```

Тело запроса:

```json
{
  "apiLogin": "API_LOGIN",
  "appId": "APP_ID",
  "clientSecret": "CLIENT_SECRET"
}
```

Из ответа необходимо получить поле `token`.

Во всех последующих запросах токен передаётся в заголовке:

```http
Authorization: Bearer TOKEN
```

## 4. Используемые методы API

### Организации

```http
POST /api/1/organizations
```

### Терминальные группы

```http
POST /api/1/terminal_groups
```

### Внешнее меню

```http
POST /api/2/menu
```

### Стоп-листы

```http
POST /api/1/stop_lists
```

### Доставочные заказы

```http
POST /api/1/deliveries/by_delivery_date_and_status
```

Пример тела запроса:

```json
{
  "organizationIds": ["ORGANIZATION_ID"],
  "deliveryDateFrom": "2026-09-14 00:00:00.000",
  "deliveryDateTo": "2026-09-16 00:00:00.000"
}
```

Дата окончания используется как верхняя граница периода. Приложение ограничивает один запрос периодом до семи дней.

## 5. Данные заказа

Для текущего проекта используются следующие поля:

| Значение | Поле iikoCloud |
|---|---|
| Номер заказа | `order.number` |
| Статус | `order.status` |
| Источник | `order.sourceKey` |
| Имя клиента | `order.customer.name` |
| Телефон клиента | `order.phone` или `order.customer.phone` |
| Сумма | `order.sum` |
| Курьер | `order.courierInfo.courier.name` |

Заказы Starter определяются по значению:

```text
order.sourceKey = Starter
```

## 6. Результат проверки

По состоянию на 15 сентября 2026 года интеграция работает:

- авторизация проходит успешно;
- доступно 10 организаций;
- доступно 11 терминальных групп;
- опубликовано 1 внешнее меню;
- получено 8 групп стоп-листов;
- заказы, включая Starter, доступны через API;
- статусы и назначенные курьеры передаются;
- контрольная проверка получила 1280 заказов;
- у 756 заказов был указан курьер;
- ошибки iikoCloud API отсутствовали.

## 7. Проверка через административную панель

Административная панель доступна без SSH-туннеля:

<https://5-129-249-100.sslip.io>

Порядок проверки:

1. Войти с учётной записью администратора.
2. Открыть раздел «iiko».
3. Выбрать период не более семи дней.
4. Нажать «Запустить проверку».
5. Проверить количество заказов, источник, статус и назначенного курьера.

Диагностика работает в режиме только чтения и не подтверждает, не отменяет и не изменяет заказы.

## 8. Что делать при отсутствии заказов

Если авторизация, организации и меню доступны, но список заказов пустой, интегратору необходимо проверить:

- привязку приложения ко всем нужным организациям;
- разрешение на получение доставочных заказов;
- доступ приложения к заказам Starter;
- наличие заказов в выбранном периоде;
- передачу заказов конкретной организации через iikoCloud API.

HTTP 200 означает только успешную обработку запроса. Наличие заказов необходимо проверять по массиву `ordersByOrganizations` в теле ответа.
