# Безопасная тестовая схема Starter → ИИ-робот → Mango

## Цель

Проверить полный разговорный сценарий на реальном заказе Starter, не звоня клиенту и не изменяя заказ в iiko.

## Неподвижные ограничения тестового режима

1. Номер клиента из iiko никогда не передаётся в Mango.
2. Исходящий вызов разрешён только на один тестовый номер из зашифрованной серверной настройки `mango_test_phone`.
3. Подмена номера через запрос браузера, параметры URL или данные заказа запрещена.
4. Запуск выполняется вручную авторизованным администратором.
5. В тестовом контуре отсутствует вызов методов подтверждения, отмены или изменения заказа iiko.
6. Результат разговора сохраняется только в локальной базе как симуляция.
7. Каждый запуск и результат фиксируются в журнале аудита.

## Поток теста

```text
iikoCloud (чтение)
        │
        ▼
Выбор заказа Starter администратором
        │
        ▼
Безопасный снимок заказа без телефона клиента
        │
        ▼
Проверка фиксированного тестового номера
        │
        ▼
Исходящий тестовый звонок через Mango
        │
        ▼
ИИ-робот озвучивает данные заказа
        │
        ▼
Тестовый пользователь подтверждает или отклоняет
        │
        ▼
Локальный результат: confirmed / rejected / operator_required
        │
        ╳
В iiko ничего не отправляется
```

## Данные, получаемые из iiko

В тестовый снимок допускается включать:

- идентификатор организации;
- номер заказа;
- источник `Starter`;
- текущий статус;
- состав заказа и модификаторы;
- сумму;
- адрес доставки;
- способ оплаты;
- желаемое время доставки;
- имя клиента.

В снимок для звонка не включается телефон клиента.

## Запуск звонка

Backend самостоятельно загружает `mango_test_phone` из зашифрованных настроек. Клиентский интерфейс передаёт только внутренний идентификатор тестового запуска и не может передать произвольный номер телефона.

Перед командой Mango выполняются проверки:

- включён тестовый режим;
- тестовый номер настроен;
- заказ получен из iiko и имеет `sourceKey = Starter`;
- для этого заказа нет уже выполняющегося теста;
- API Key и Salt Mango настроены;
- SIP/API-контур Mango находится в рабочем состоянии.

## Поведение ИИ-робота

Робот получает неизменяемый снимок заказа и может:

- выбрать приветствие «Доброе утро», «Добрый день» или «Добрый вечер» по времени ресторана;
- обращаться к клиенту по имени и говорить о себе в женском роде;
- озвучить каждую позицию и модификатор с количеством, сумму, адрес и способ оплаты;
- спросить, подтверждает ли тестовый пользователь заказ, адрес и способ оплаты;
- принять устную корректировку и повторить весь заказ с изменением для повторного подтверждения;
- уточнить ответ;
- передать результат серверному инструменту;
- завершить разговор или отметить необходимость оператора.

Единственный изменяющий инструмент тестовой сессии:

```text
record_test_confirmation(result, comment)
```

Допустимые результаты:

- `confirmed`;
- `rejected`;
- `operator_required`;
- `no_answer`;
- `technical_error`.

Инструмент записывает результат только в локальную базу. Инструменты изменения iiko не подключаются к тестовой сессии.

## Что отображается в админке

- выбранный заказ и его снимок;
- тестовый номер в маскированном виде;
- состояние запуска;
- состояния звонка Mango;
- текстовая расшифровка;
- результат симуляции;
- отметка «В iiko не отправлено»;
- технические ошибки и время каждого этапа.

## Этапы реализации

1. Подписанный callback `/mango/events/call` и журнал событий.
2. Получение `vpbx_api_key` и `vpbx_api_salt`, проверка реального уведомления Mango.
3. Сохранение единственного тестового номера и серверный allowlist.
4. Автоматический выбор последнего подтверждённого заказа Starter и создание снимка состава, суммы и адреса без телефона клиента.
5. Ручной тестовый вызов через Mango только на разрешённый номер.
6. Подключение Yandex SpeechKit для распознавания и синтеза и YandexGPT для диалога.
7. Локальный инструмент симуляции подтверждения.
8. Приёмочная проверка отсутствия запросов изменения в iiko.
